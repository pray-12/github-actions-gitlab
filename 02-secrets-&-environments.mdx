## What are Secrets?

Secrets store sensitive data such as:

- AWS Access Keys
- Docker Hub Passwords
- API Tokens
- Database Passwords
- SSH Keys

GitHub encrypts them and masks them in logs.

## Where Are Secrets Stored?

Repository Level:

```yaml
Repository
   ↓
Settings
   ↓
Secrets and Variables
   ↓
Actions
```
## Using Secrets in Workflow

Syntax:

```yaml
${{ secrets.SECRET_NAME }}
```

Example:

```yaml
env:
  AWS_ACCESS_KEY_ID: ${{ secrets.AWS_ACCESS_KEY_ID }}
```

## Example: Docker Login

Store:

```yaml
DOCKER_USERNAME
DOCKER_PASSWORD
```

Workflow:

```yaml
- name: Docker Login
  run: |
    docker login \
    -u ${{ secrets.DOCKER_USERNAME }} \
    -p ${{ secrets.DOCKER_PASSWORD }}
```

## Example: SonarQube Token

Store:

```yaml
SONAR_TOKEN
```

Use:

```yaml
- name: Sonar Scan
  run: mvn sonar:sonar
  env:
    SONAR_TOKEN: ${{ secrets.SONAR_TOKEN }}
```

## What Are Environments?

Environments provide deployment protection and environment-specific secrets.

Examples:

```yaml
Development
Staging
Production
```

## Why Use Environments?

Without environments:

```yaml
One Secret Set
```

Problem:

```yaml
Dev and Prod use same credentials
```

Bad practice.

Environment-Based Deployment

```yaml
Dev Environment
      ↓
Dev Secrets

Stage Environment
      ↓
Stage Secrets

Production Environment
      ↓
Production Secrets
```

```yaml
jobs:
  deploy:
    environment: production

    runs-on: ubuntu-latest

    steps:
      - run: echo "Deploying"
```

# GitHub Actions Secrets & Environments - Interview Questions and Answers

## 1. What are GitHub Secrets?

**Answer:**

GitHub Secrets are encrypted values used to securely store sensitive information such as:

- API Keys
- AWS Credentials
- Docker Hub Passwords
- SonarQube Tokens
- Slack Webhooks

Secrets prevent sensitive data from being exposed in source code or workflow files.

## 2. How do you access a secret inside a workflow?

**Answer:**

Use the following syntax:

```yaml
${{ secrets.SECRET_NAME }}
```

Example:

```yaml
env:
  AWS_ACCESS_KEY_ID: ${{ secrets.AWS_ACCESS_KEY_ID }}
```

## 3. Where are GitHub Secrets stored?

**Answer:**

Repository-level secrets are stored under:

```text
Repository
 └── Settings
      └── Secrets and Variables
           └── Actions
```

Organization secrets are stored at the organization level and can be shared across repositories.

## 4. What is the difference between Secrets and Environment Variables?

**Answer:**

| Secrets | Environment Variables |
|----------|----------|
| Encrypted | Plain text |
| Used for sensitive data | Used for non-sensitive data |
| Masked in logs | Visible in logs |
| Stored securely | Stored directly in workflow |

Example:

```yaml
env:
  APP_NAME: netflix
```

```yaml
env:
  AWS_KEY: ${{ secrets.AWS_KEY }}
```

---

## 5. What happens if a secret is printed in workflow logs?

**Answer:**

GitHub automatically masks secret values.

Example:

```text
***
```

instead of:

```text
mypassword123
```

This prevents accidental exposure of sensitive information.

---

## 6. What are Repository Secrets?

**Answer:**

Repository Secrets are available only to a specific repository.

Example:

```text
Repository A
    ↓
AWS Credentials
```

They cannot be accessed by other repositories.

---

## 7. What are Organization Secrets?

**Answer:**

Organization Secrets are shared across multiple repositories within a GitHub organization.

Example:

```text
Organization
      ↓
AWS Credentials
      ↓
Repo A
Repo B
Repo C
```

This helps centralize credential management.

---

## 8. What is a GitHub Environment?

**Answer:**

A GitHub Environment represents a deployment target and can have:

- Environment-specific secrets
- Deployment approvals
- Protection rules

Examples:

```text
Development
Staging
Production
```

---

## 9. How do you associate a job with an environment?

**Answer:**

Use the `environment` keyword.

Example:

```yaml
jobs:
  deploy:
    environment: production
    runs-on: ubuntu-latest
```

GitHub automatically loads environment-specific secrets and rules.

---

## 10. What are Environment Secrets?

**Answer:**

Environment Secrets are secrets specific to a particular environment.

Example:

```text
Development Environment
    ↓
DEV_AWS_KEY

Production Environment
    ↓
PROD_AWS_KEY
```

This ensures different credentials are used for different environments.

---

## 11. What are Deployment Protection Rules?

**Answer:**

Protection rules help secure deployments by enforcing:

- Manual approvals
- Required reviewers
- Wait timers
- Branch restrictions

These rules are configured at the environment level.

---

## 12. How do Environment Approvals work?

**Answer:**

Workflow execution pauses until an authorized reviewer approves deployment.

Flow:

```text
Workflow Starts
      ↓
Deployment Job
      ↓
Approval Required
      ↓
Reviewer Approves
      ↓
Deployment Continues
```

---

## 13. Why should production deployments use Environment Approvals?

**Answer:**

Benefits:

- Prevent accidental deployments
- Add governance and control
- Require management approval
- Improve deployment security

This is a common practice in enterprise CI/CD pipelines.

---

## 14. Can Secrets be used inside `run` commands?

**Answer:**

Yes.

Example:

```yaml
steps:
  - name: Login to DockerHub
    run: |
      docker login \
      -u ${{ secrets.DOCKER_USERNAME }} \
      -p ${{ secrets.DOCKER_PASSWORD }}
```
